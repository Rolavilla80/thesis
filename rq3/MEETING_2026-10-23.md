# Meeting 2026-10-23 — grapheme-level frame shift: final numbers, and the thesis plan

## 1. The question, as sharpened by your feedback

`_cb` stops BPE from merging across a character boundary while the character is incomplete
(Thai ก = E0 B8 81: the prefix E0 B8 may be learned, 81 + E0 may not). Does the same frame shift recur one
level up, across grapheme boundaries? Example กิน = ก + ิ + น: `ก | ิ | น` is incomplete but harmless;
`ก | ิน` is the defect, the mark ิ torn from ก and glued to น.

Measured with your two metrics: (1) how many such tokens exist and how often they are emitted,
(2) what it costs in compression to disallow them.

## 2. Results

Two constraints were tested. *Strict* = my first version (also blocks marks-only tails such as ี่ and tokens
ending in a virama). *Relaxed* = exactly your formulation: reject a token only if it starts with a combining mark
and continues into the next grapheme; everything else tolerated.

| language | target tokens in vocabulary, `_cb` → relaxed | emitted per 1,000 tokens on FLORES, `_cb` → relaxed | tokens on FLORES, `_cb` → relaxed | chars/token, `_cb` → relaxed |
|---|---|---|---|---|
| Thai | 990 → 0 | 10.8 → 0.0 | 22,728 → 22,861 (+0.6%) | 6.81 → 6.74 |
| Punjabi | 2,381 → 0 | 11.6 → 0.0 | 31,538 → 31,520 (−0.1%) | 5.43 → 5.45 |
| Arabic | 770 → 0 | 7.8 → 0.0 | 26,283 → 26,372 (+0.3%) | 5.66 → 5.66 |
| Hindi | 2,451 → 0 | 16.3 → 3.6 | 30,809 → 30,790 (−0.1%) | 5.61 → 5.65 |
| Hebrew | 339 → (not retrained) | 0.0 (FLORES Hebrew is unpointed) | | |
| German | 0 | 0.0 | | |

Under `_cb` the first such token appears at merge rule 34 in Thai and Hindi (`่า`, `ार`), rule 45 in Punjabi,
rule 180 in Arabic. The vocabulary's top target tokens rarely surface on FLORES, because the frequent words that
contain them became whole tokens; what surfaces is the long tail (ร|่าง, ม|ิน, ज़|ेशन, ਲ|ਿੰਗ).

Three things the table does not show:

- **Encoding does not matter.** The SCRIPT-encoding tokenizers (`scriptenc_gpt4o_cb`) learn the identical target
  tokens and make the identical cuts on FLORES as the byte tokenizers, for every language. The defect lives in
  the constraint level, not the atom level.
- **The tolerated class is independent.** When marks-only tails are allowed again (relaxed), BPE re-learns about
  as many of them as under `_cb` (Thai 19, Hindi 33, Punjabi 40, Arabic 9), while the target class stays at 0.
- **Hindi keeps a residual of a different kind.** The remaining 3.6 per 1,000 are consonants cut from their
  conjunct after a virama (ल्|लियाँ, ज़्|यादातर). A left-edge rule cannot see them. The right-edge rule that
  would (no token may end in a virama) is the strict version, which makes conjuncts unassemblable:
  +28.5% tokens and 72.9 cross-grapheme cuts per 1,000. So that residual is the limit of a type-level constraint.

## 3. What I propose to write (last part of the thesis)

1. The analogy and the definition (one page, the two examples above).
2. Where `_cb` stops: decodable tokens are never inspected, so `ิน` is legal for it.
3. Four levels of measurement for Thai: 990 types → 13.3 M merge operations (4.8%) → 217,538 still standing at
   the end of training → 245 emitted on FLORES. With the caveat that merge operations are not text positions.
4. The cross-language table above, plus the Hebrew caveat and the encoding result.
5. The constraint: strict vs relaxed, the Hindi lock, cost table.
6. Limits: type-level rules cannot see context (Hindi residual); FLORES cannot test Hebrew; no downstream
   evaluation (as agreed).
